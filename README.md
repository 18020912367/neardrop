# 邻传 NearDrop

一个在本地局域网内传输文件的 Web 服务。两台设备连接同一个 Wi-Fi，用浏览器打开同一个地址，就能互相发现、双方确认连接，然后把文件发送到对方的浏览器下载目录。**无需安装客户端，不经过云端，也没有配对码。**

## 功能

- **自动发现**：同一局域网内的设备打开页面后自动出现在「附近设备」列表。
- **双向握手**：一方点选对方，另一方在自己的页面上确认，双方一致后才建立传输通道。
- **双方互传**：通道建立后，任意一方都可以向对方发送文件。
- **文件确认**：接收方会看到文件清单，可选择接收或拒绝。
- **自动保存**：传输完成后默认自动交给浏览器下载到默认下载目录；如果浏览器拦截了多文件下载，可以在页面里点「保存全部」或单个文件的「保存」。
- **实时进度**：显示每个文件的传输状态、百分比和大小。
- **多文件**：一次最多 100 个文件；支持任意类型、空文件和中文文件名。
- **断线保护**：SSE 自动重连；服务重启后页面会自动重新加入局域网。
- **零运行时依赖**：只用 Node.js 内置模块，`npm install` 都不需要。

## 快速开始

### 环境要求

- Node.js **18 或更高版本**（推荐 20+）。
- 两台设备连接同一个局域网 / Wi-Fi。

### 启动

在项目目录执行：

```bash
npm start
```

或者直接：

```bash
node server.js
```

Windows 下也可以双击 `start.cmd`。如果 Node.js 已安装但不在 PATH 中，可以先设置 `NEARDROP_NODE` 指向 `node.exe` 的完整路径。

启动后终端会打印本机地址和局域网地址，例如：

```
本机访问   http://localhost:8787
局域网访问 http://192.168.0.3:8787  (以太网)
```

让**另一台设备用浏览器打开「局域网访问」那个地址**。不要用 `localhost`，因为它只指向设备自己。

> 第一次启动时，Windows 可能会弹出 Node.js 防火墙提示，请允许「专用网络」访问。如果其他设备打不开页面，请检查防火墙、访客网络或路由器的 AP 隔离设置。

### 使用

1. 两台设备打开同一个局域网地址，顶部会显示「局域网在线」。
2. 在左侧「附近设备」中点击对方。
3. 对方页面会弹出连接请求，点「接受连接」。
4. 双方都看到「通道已建立」后，选择文件并点「发送给 …」。
5. 对方确认接收后，文件开始传输。接收方默认会在文件到达时自动交给浏览器下载到默认下载目录；如果浏览器弹出「允许下载多个文件」的提示，请选择允许。如果文件没有出现在下载目录，可以点「保存全部」或每个文件右侧的「保存」按钮再次交给浏览器。

## 配置

通过环境变量调整：

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `PORT` | `8787` | 监听端口 |
| `HOST` | `0.0.0.0` | 监听地址；默认允许局域网访问 |
| `DATA_DIR` | `.data` | 临时文件中转目录 |
| `MAX_FILE_SIZE` | `10737418240`（10 GiB） | 单文件上限（字节） |
| `MAX_BATCH_SIZE` | `21474836480`（20 GiB） | 单批文件总大小上限（字节） |

PowerShell 示例：

```powershell
$env:PORT=9000
node server.js
```

## 工作方式

```
浏览器 A ──HTTP/SSE──┐
                     ├── Node.js 本地服务 ── 临时文件 (.data)
浏览器 B ──HTTP/SSE──┘
```

- 设备在线状态、连接请求、文件请求和进度使用 **Server-Sent Events (SSE)** 实时推送。
- 文件使用 **XHR PUT** 流式上传到本地服务，服务再以带随机令牌的下载链接提供给接收方，因此下载由接收设备的浏览器原生下载管理器完成。
- 服务不依赖 WebRTC、不需要 STUN/TURN，也不依赖公网。
- 临时文件默认保留 6 小时；服务启动时会清空上次的临时目录。所有客户端和会话状态保存在内存中。

## 安全说明

- 服务面向**可信局域网**设计，默认监听所有网卡。请不要把它直接暴露到公网，也不要在公共 Wi-Fi 上使用。
- 每个设备有随机的客户端令牌；下载链接包含独立的高熵随机令牌。文件名不会用作服务器磁盘路径。
- 局域网内任何能访问该地址的人都可以注册并出现在设备列表里。连接和文件传输必须经过对方确认。
- 当前版本通过 HTTP 在局域网内传输，不是 TLS 加密连接；请只在受信任的网络中使用。

## 常见问题

**另一台设备看不到我 / 打不开页面**

- 确认地址栏使用终端打印的局域网 IP 地址，而不是 `localhost`。
- 确认两台设备在同一个 Wi-Fi / 局域网，且没有连接访客网络。
- 在 Windows 防火墙中允许 Node.js 通过专用网络；同时检查路由器是否开启了「AP 隔离」。
- 如果电脑有多张网卡（有线、无线、VPN），终端会列出所有可用地址，换一个尝试。

**文件没有出现在下载目录 / 自动保存没有反应**

浏览器的安全模型不允许网页静默写入任意文件夹，网页只能把文件交给浏览器的下载管理器。默认的「自动保存」会在文件到达时自动触发下载；若浏览器拦截了非用户手势触发的下载、或一次下载多个文件，文件可能没有落盘。

- 检查传输动态右上角的「自动保存」开关是否已打开。
- 如果一次传输多个文件，浏览器通常会询问是否允许下载多个文件，请选择允许。
- 点击「保存全部」或单个文件的「保存」按钮作为兜底。
- 下载位置由浏览器的「下载」设置决定。

纯网页无法绕过浏览器直接写入指定文件夹；如果必须静默写入固定目录，需要改为桌面客户端或使用浏览器目录授权 API（需要 HTTPS 且目前仅部分 Chromium 浏览器支持）。

**刷新页面后传输失败**

正在上传的文件由发送方浏览器读取原始文件，刷新或关闭页面会让它无法继续。页面会显示提示，取消本批传输后重新选择文件即可。已经完成传输的文件不受影响。

**手机端可以用吗？**

可以。页面为手机/平板做了响应式布局，下载行为由手机浏览器决定（部分手机会先预览再保存）。
